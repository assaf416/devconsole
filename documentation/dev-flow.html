⚡ תהליך פיתוח Feature

מה ה-AI עושה מהרגע שמבקשים ממנו לפתח פיצ'ר חדש

STEP 01
💬
קבלת הבקשה וניתוחה
מנתחים את הבקשה: מה הפיצ'ר, מה הסוג (bug / feature / refactor), ומה ה-scope. בודקים אם יש stories.json, repo memory ו-instructions רלוונטיות.
📂 /memories/repo/ 📂 /memories/development-process.md copilot-instructions.md
הבנת הקשר
STEP 02
🔍
חקירת ה-Codebase
קוראים קבצים רלוונטיים, מחפשים patterns קיימים, מבינים את ה-schema ואת מבנה ה-routes. לא מניחים הנחות — קוראים קודם.
read_file grep_search semantic_search file_search
app.rb views/ features/ Gemfile db schema
הקשר מלא
STEP 03
📋
פתיחת GitHub Issue בעברית
יוצרים Issue עם: כותרת בעברית, תיאור שינוי, שעות משוערות, בדיקת Cucumber מוצעת ופתרון מוצע — לפי ה-instructions.md.
🐙 mcp_github_create_issue github-issues.instructions.md
כותרת בעברית ✓ שעות משוערות ✓ Cucumber מוצע ✓
issue #{n} נפתח
STEP 04
🌿
יצירת Feature Branch
יוצרים branch בשם ST-XXX-תיאור-באנגלית מ-main. שם ה-branch נגזר מה-story ID והכותרת.
git checkout -b ST-XXX-... 🐙 mcp_github_create_branch
TDD first
STEP 05
🥒
כתיבת Cucumber בעברית — קודם כל
כותבים Feature File עם # language: he, תרחישים בעברית, Step Definitions. הבדיקות אמורות להיות אדומות עדיין.
create_file / replace_string_in_file cucumber-hebrew.instructions.md bundle exec cucumber
תכונה: ... תרחיש: ... בהינתן / וכאשר / אז 🔴 RED
implement
STEP 06
⚙️
מימוש הפיצ'ר
כותבים את הקוד עצמו — routes, helpers, views, DB migrations. עורכים קבצים קיימים ויוצרים חדשים לפי הצורך. לא מוסיפים מעבר למה שנדרש.
replace_string_in_file create_file ruby-sinatra.instructions.md
app.rbviews/*.erb app.cssdb migration
ריצת בדיקות
STEP 07
🧪
ריצת כל הבדיקות
מריצים Cucumber במצב שקט. אם יש כשל — קוראים את הפלט, מתקנים ומריצים שוב. לא מתקדמים עד שהכל ירוק.
CUCUMBER_PUBLISH_QUIET=true bundle exec cucumber
🟢 X scenarios passed 0 failures
ירוק ✓
STEP 08
📤
Commit + Push
מוסיפים את כל השינויים ל-staging, יוצרים commit עם הודעה ברורה ודוחפים ל-origin.
git add . git commit -m "ST-XXX: ..." git push origin ST-XXX-...
PR נפתח
STEP 09
🔀
פתיחת Pull Request + ממתינים ל-CI
פותחים PR ל-main דרך GitHub MCP. בודקים שה-CI Actions עוברות. אם CI אדום — מאבחנים ומתקנים.
🐙 mcp_github_create_pull_request 🐙 mcp_github_list_workflow_runs troubleshoot skill
🟢 CI passed
merge
STEP 10
🎉
Merge + סגירת Issue + עדכון זמן
ממזגים את ה-PR ל-main, סוגרים את ה-Issue ומעדכנים את ה-body עם: שעות בפועל, קישור ל-branch, קישור ל-PR וקישורים לכל קבצי ה-Cucumber שנוצרו.
🐙 mcp_github_merge_pull_request 🐙 mcp_github_update_issue 🐙 mcp_github_close_issue
✅ Done שעות בפועל ✓ 🔗 branch link ✓ 🔗 PR link ✓ 🥒 feature files ✓ issue סגור
